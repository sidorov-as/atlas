# C4

Optional; requires Standard Catalog. Adds no Entity Kind of its own; it renders diagrams over
entities that other plugins own, targeted by capability rather than by kind id.

## What it targets

The diagram tab this plugin contributes to an entity's detail page is gated on
`entitySupports('architecture.subject.v1')`, the same capability Standard Catalog's `system` and
`component` kinds declare, rather than a hard-coded check for those kind ids. This is the
mechanism described in [Extension points & capabilities](../extension-points.md): this plugin
never needs to know which kinds exist, only which capability they declare.

## Contributions

- A route (`/architecture`) rendering the catalog-wide System Landscape diagram.
- An entity detail tab rendering that entity's own architecture diagram, gated by
  `architecture.subject.v1` and requiring the `atlas.c4.diagram.read` permission this plugin
  registers.
- A home widget summarizing the landscape.

## Rendering

The server generates diagrams from catalog entities and their relationships. It translates them
into PlantUML-compatible payloads and renders them locally, without a client-side diagram engine or
externally hosted rendering service involved. Diagram endpoints return SVG by default and accept
a PNG or attachment-download variant.

## Permission

`atlas.c4.diagram.read` is registered at startup and checked through the distribution's Policy
Evaluator like every other permission id.
