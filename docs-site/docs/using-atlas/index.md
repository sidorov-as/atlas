# Using Atlas

This section is for people who browse and maintain catalog data in Atlas. It
covers the identity, ownership, relationship, and lifecycle rules that
determine the actions available for an entity.

## Who this section is for

Follow this path if you use Atlas to find software, inspect ownership and
relationships, or maintain entity records. It answers:

- how to browse, search, filter, preview, and open catalog entities;
- which entity kinds Atlas currently supports;
- how names, namespaces, owners, and references identify catalog data;
- why manual and repository-managed entities behave differently; and
- where feature-specific views such as APIs, diagrams, and schemas fit.

## Start here

Start with [Browse the catalog](browse-catalog.md) to find and inspect an entity
using the current UI. Follow its links to the concepts behind each catalog
field when you need more context.

## Recommended path

1. [Browse the catalog](browse-catalog.md): use navigation, search, filters,
   pagination, previews, and ownership views to find an entity.
2. [Inspect entity details](inspect-entity-details.md): read ownership,
   documentation, relations, state indicators, and contributed tabs.
3. [Create or edit catalog entities](create-edit-entities.md): use the
   supported manual UI and admin maintenance paths.
4. [Choose the correct entity workflow](choose-entity-workflow.md): match
   provenance, lifecycle, and availability to a safe action.
5. [Register and ingest a repository](ingest-repository.md): configure a git
   source and verify its reconciled catalog records.
6. [Troubleshoot repository ingestion](troubleshoot-ingestion.md): correct
   validation, claim, retry, and unregistration failures safely.
7. [Manage an entity's lifecycle](manage-entity-lifecycle.md): remove,
   revive, or permanently purge an entity with the correct authority.
8. [Use feature-specific catalog views](use-feature-views.md): continue from
   entity context into APIs, diagrams, schemas, and Flows.
9. [Entity model](../concepts/entity-model.md): learn the supported catalog
   kinds and their roles.
10. [Entity references](../concepts/entity-references.md): understand how
   owners, systems, dependencies, and other links resolve.
11. [Life of an entity](../concepts/life-of-an-entity.md): distinguish manual,
   ingested, unavailable, removed, revived, and purged states.
12. [Permissions](../concepts/permissions.md): see how identity, ownership, and
   grants affect catalog actions.
13. [Standard Catalog](../features/standard-catalog.md):
   connect the shared concepts to the built-in catalog surface.
14. Continue into [Features and Integrations](../features/index.md) for APIs, C4
   diagrams, database schemas, and ingestion behavior.

## Section boundary

This section explains catalog-user workflows and their lifecycle effects. It
does not cover service configuration or distribution maintenance; operators
should use [Operating Atlas](../operating-atlas/index.md). Exact manifest
fields and API contracts belong in [Reference](../reference/index.md).
