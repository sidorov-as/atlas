## Why

The Flow visual editor lets an author freely retype a step's `title`/`summary` even after picking a catalog reference (`entity_ref`), and freely retype a step's `id` even though `id` is purely an implementation detail used only for transition wiring. Once both are freely editable, an entity-backed node can end up showing text with no relationship to what was actually picked — visually indistinguishable from a fully custom step, with the reference reduced to invisible metadata. That defeats the point of picking a structured reference in the first place: a reader of the diagram can no longer trust that what's rendered matches the catalog. Reviewing this area also surfaced two smaller, related gaps: the JSON rail commits structurally-broken edits (e.g. a renamed step id that orphans a `next_step`) straight to the canvas and only errors at Save, and the "Add Step" picker's Component tile shows a green that no real Component ever renders on canvas.

## What Changes

- **Entity-backed steps (Actor/Team/Component/Data/API/System) no longer have editable Title/Summary.** The step-edit modal drops those inputs for these six kinds (Step and External keep their own free-text Title/Summary, unchanged). The canvas card always renders the *live* referenced entity's current title/description — never a value typed into the step. Saving a step that carries both a non-empty `entity_ref` and a non-empty `title`/`summary` is rejected, enforced server-side (not just hidden in the UI) so the JSON rail can't reintroduce it.
- **API Call/Event steps lose editable Title/Summary too** (scope widened during implementation, after manual QA showed the same divergent-text problem applies to them). The card always renders the picked Endpoint's/Operation's own snapshotted method+path or channel+direction as its title, and that Endpoint's/Operation's own `summary` (also snapshotted at pick time, falling back to the owning API's raw name when blank) as its subtitle — derived from the step's already-stored `query_ref`/`event_ref`, no live fetch. The same server-side save-time rejection covers `query_ref`/`event_ref` + non-empty `title`/`summary`.
- **A step's `id` is no longer a visual-editor field**, for any step kind. It's auto-generated for a new step and can only be set/renamed by hand-editing the JSON rail.
- **The JSON rail starts collapsed**, not open, on the Flow edit page.
- **The JSON rail's edits are gated on structural validity, not just shape**, before they reach the canvas. Today, typing JSON that parses but breaks referential integrity (a duplicate id, a transition to a nonexistent step, a reconverging branch, a cycle) already updates the canvas — with the resulting broken diagram not caught until the author tries to Save. Going forward, the canvas keeps showing its last valid state and the rail shows the specific error inline until the typed JSON is both shape-valid and structurally valid.
- **"Add Step" picker fix**: System's tile/canvas color changes from blue (shared with API) to green, matching no other kind. Component's tile color changes from green to blue — the green it showed today never corresponds to any real Component's actual (subtype-derived) canvas color. The picker's 2×5 grid is reordered so no two adjacent tiles (same row or column) share a color.
- **Stale-reference detection and refresh extend to the newly-added `summary` snapshot** (found post-deploy: a real Flow's `query_ref`/`event_ref` summary had drifted from its live Endpoint/Operation with no warning shown at all). `flow-stale-ref-refresh`'s existing drift check — previously `event_ref.direction`/`event_ref.channel` only — now also compares each ref's `summary` against its resolved Endpoint's/Operation's current one, independently of the direction/channel comparison. This closes a gap the `summary` snapshot itself introduced, and, since `query_ref.summary` can now drift too (unlike `method`/`path`), extends the existing warning-icon-plus-refresh-control pattern to API Call nodes for the first time — previously exempt entirely, since nothing on a `query_ref` could ever drift.
- **The canvas card's refresh control now applies directly, without opening the edit modal** (found in review: the extra "open modal, click Save" round trip was pure friction for a change that's already exactly as reversible as any other canvas edit — matching the precedent `removeSteps`, the node's delete control, already sets). The modal's own refresh control — reachable when a stale step happens to already be open there — is unchanged: it still only fills the modal's form, committed by the modal's own Save.

## Capabilities

### New Capabilities
_None._

### Modified Capabilities
- `visual-flow-editor`: "Catalog entity lookup for Flow steps" (entity-backed Title/Summary become non-editable/live, not prefilled-then-freeform); a new requirement covering API Call/Event's own Title/Summary removal, rendering from the `query_ref`/`event_ref` snapshot instead; "Visual Flow step authoring" / a new requirement (step `id` is never a visual-editor field); "Visual editor structural feedback" (duplicate-id-via-modal scenario removed, cross-referenced to the JSON-rail gate); "Synchronized Visual and JSON modes" (rail defaults collapsed; sync now gated on structural validity, not just shape); a new requirement for the "Add Step" picker's tile colors and adjacency rule; "Stale Endpoint/Operation reference indicator" and "Refresh action pulls live values into a stale step's ref" (both `flow-stale-ref-refresh`, already archived; the latter renamed from "...edit inputs") extended to also cover `summary` drift for both API Call and Event, dropping the prior "API Call SHALL NOT show this control" restriction now that a `query_ref.summary` can drift too, and changed so the canvas card's own control applies directly (no modal) while the modal's own control (reachable when a step happens to already be open there) still only fills the form, committed by the modal's Save.
- `flow-management`: "Reading a Flow surfaces live status of entity_ref-targeted entities" extended to always include the resolved entity's `title`/`description`, not only `status`/`deprecated` — rendering now depends on this data, not just diagnostics.
- `flow-query-event-steps`: "Reading a Flow surfaces live status of referenced Endpoints/Operations" (`flow-stale-ref-refresh`, already archived) extended so the `summary` comparison applies to `query_ref` too, not just `event_ref`'s existing `direction`/`channel` comparison — independently of it.
